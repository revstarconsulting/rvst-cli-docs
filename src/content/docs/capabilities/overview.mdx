title: Capabilities overview
description: The capability kinds Kiro Workbench v1 installs, and how they layer together.
---

Kiro Workbench installs four kinds of capability, plus two systems built on top
of them. They layer on top of each other rather than working in isolation:

- **[Steering](/capabilities/steering/)** — always-on rules. Loaded into every
  turn automatically, so it is kept to a handful of short files.
- **[Skills](/capabilities/skills/)** — on-demand playbooks. An agent loads a
  skill's body only when your request matches its trigger; the metadata is the
  only part that costs anything up front.
- **[Agents](/capabilities/agents/)** — the personas that use steering and
  skills to do the work. Each has a fixed model and a fixed set of tools.
- **[Gates](/capabilities/gates/)** — enforcement hooks wired into the agents.
  Every gate is **inert until armed** with a `.enabled` flag file, and every
  gate **fails open** — a crashing or unarmed gate never blocks you silently.

## Two systems built on these primitives

- **Missions** — a standing macro-goal for multi-phase work, kept alive across
  context compaction by the `mission-inject` and `mission-turn-recorder` gates.
  See the `mission` skill.
- **Memory** — a knowledge base of durable environment facts and standing
  preferences, indexed and retrieved on demand rather than loaded every turn
  like steering is.

## How a task flows

1. **Steering** is already in context — conduct, token efficiency,
   engineering invariants, QA/mission triggers, secrets handling.
2. You (or a mission) invoke a **skill** that matches the task; its body loads
   only now.
3. The active **agent** — `dev`, `coder`, or `scout` — carries out the skill
   using the tools it's permitted.
4. Any **gate** wired to that agent's tool calls enforces its rule, if armed.

## Your installed version

These docs track the **v1** line; new capabilities are added bolt-on, never by
subtracting. For the exact version installed on your machine:

```sh
kiroctl version
kiroctl doctor
```

`kiroctl doctor` also validates governance — model routing, gate wiring, and
steering/skill integrity — in one pass.
