## Prerequisites

- **Node.js 18+**
- **git**
- **[Kiro CLI](https://kiro.dev)** (`kiro-cli`) installed and on your `PATH`

## Clone both repos

Kiro Workbench is delivered as two repos, cloned **side by side**:

```sh
git clone https://github.com/revstarconsulting/rvst-cli.git
git clone https://github.com/revstarconsulting/rvst-registry.git
```

`rvst-cli` holds the `kiroctl` CLI and its installers. `rvst-registry` holds the
content pack — agents, skills, gates, steering — that the installer bootstraps
into your Kiro configuration.

## Run the installer

From inside `rvst-cli`, point the installer at your `rvst-registry` clone with
`KIRO_REGISTRY_ROOT`:

<Tabs syncKey="os">
  <TabItem label="macOS" icon="apple">
    ```sh
    KIRO_REGISTRY_ROOT=../rvst-registry ./installers/install-macos.sh
    ```
  </TabItem>
  <TabItem label="Linux" icon="linux">
    ```sh
    KIRO_REGISTRY_ROOT=../rvst-registry ./installers/install-linux.sh
    ```
  </TabItem>
  <TabItem label="Windows" icon="seti:windows">
    Run in PowerShell:
    ```powershell
    $env:KIRO_REGISTRY_ROOT="..\rvst-registry"
    .\installers\install-windows.ps1
    ```
  </TabItem>
</Tabs>

Add `--arm-safe` to also arm the inject-only gates (the ones that cannot block
anything — they only inject mission state and write turn receipts):

```sh
KIRO_REGISTRY_ROOT=../rvst-registry ./installers/install-macos.sh --arm-safe
```

### What the bootstrap does

1. Copies `steering/` and `skills/` from the registry into `$KIRO_HOME`.
2. Writes the `dev`, `coder`, and `scout` agent configurations.
3. Sets `chat.defaultAgent` to `dev`.
4. Asserts the model pins (Opus for `dev`, Sonnet for `coder`/`scout` — never
   Haiku, never `auto`).
5. Runs the governance guard, which validates the installed configuration
   against the registry's rules.
6. Wires the Playwright and Azure DevOps MCP servers.
7. Links the `kiroctl` binary onto your `PATH`.
8. Records an install manifest, so `kiroctl doctor` and `kiroctl update` know
   exactly what was installed and from where.

<Aside type="note">
`$KIRO_HOME` defaults to `~/.kiro` and honors the `KIRO_HOME` environment
variable if you keep separate profiles on one machine.
</Aside>

## Verify

```sh
kiroctl doctor
node ../rvst-registry/kiro/gates/selftest.js
kiroctl doctor --governance
```

`kiroctl doctor` reports the install is healthy. The gate selftest should print
**60/60** — every gate case asserted in both directions. `kiroctl doctor
--governance` should report **OK**.

## Updating later

```sh
kiroctl update
```

This performs a verified pull of both repos and reinstalls — bolt-on, never
subtract, so your own customizations are preserved.
