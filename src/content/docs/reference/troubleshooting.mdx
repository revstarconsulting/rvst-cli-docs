---
title: Troubleshooting
description: Fixes for the v1 issues developers actually hit.
---

| Symptom | Fix |
| --- | --- |
| Install stops with `FATAL: no co-located kiro/ and KIRO_REGISTRY_ROOT is not set` | Pass the registry location explicitly: `KIRO_REGISTRY_ROOT=../rvst-registry`. |
| A bare `kiro-cli` says `profileArn is required` | Don't launch `kiro-cli` directly. Launch via `kiroctl open` (or the platform launcher), which handles client login first. |
| A gate doesn't fire | Confirm its `.enabled` flag file actually exists, then run `node kiro/gates/selftest.js` to isolate which gate is misbehaving. |
| ADO tools return `401` or no data | Your PAT isn't set (or lacks scope). Set it with `kiroctl client set-pat`, using a token with **Work Items Read & Write**. |
| `kiroctl update` says `unknown layout` | Pass the registry location explicitly with `--registry <path>`, or `git pull` each clone and reinstall. |
| Registry signature verification failed | The manifest must be signed with the key matching `kiroctl`'s embedded public key. A manifest signed with a different key will always fail verification. |
| Changes not taking effect | Restart the `kiro-cli` session. Steering, skills, and MCP servers all load at session start — an edit made mid-session isn't picked up until the next one. |
| `kiro-cli` behaves oddly / features silently fail on an older install | Your `kiro-cli` may be out of date. Run `kiroctl doctor` — it now **WARNs** when `kiro-cli` is below the recommended version. Update via the installer at `cli.kiro.dev/install`, then restart the session. |
| QA render can't launch a browser on Linux (no display) | A headed browser needs a display server. On a display-less Linux host, install Xvfb (`sudo apt-get install -y xvfb`); the pack auto-wraps the Playwright MCP in `xvfb-run` so the render stays headed. macOS and Windows aren't affected. |
| A shell command hangs for many minutes on macOS with no timeout | Known `kiro-cli` limitation: on macOS its shell tool has no per-command timeout (Windows times out on its own). Recovery: tell the agent "the shell has been pending for N minutes," then press **Enter → Escape** to move it to the pending queue so it re-routes. Prefer backgrounding long-running commands (dev servers, installs). Reported upstream. |
| ADO PAT is set but the session still can't use it (or uses an old one) | The PAT is injected when you **`open`** the project. Set it *before* opening; if you change it, **relaunch** the session — a running session keeps the value it launched with. |
| An MCP server shows a failure on first startup | Often a cold-start flake (e.g. `npx` fetching the server on first run). Restart the session and it usually clears. If it persists, run `kiroctl doctor` and check `~/.kiro/settings/mcp.json`. |
