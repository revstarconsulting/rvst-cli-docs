## Philosophy: bolt-on, never subtract

Kiro Workbench is designed to be customized in place. Steering, skills, and
agents in your project are yours to edit — the tooling is built so that
pulling in a newer version of the registry **adds and updates**, it never
silently removes or overwrites work you've done.

## Updating is conflict-safe

**`kiroctl sync`** (and `kiroctl update`) are the mechanisms that pull registry
changes into a project, and both are **edit-preserving**:

- Every installed file has a **content hash** recorded at install/onboard time.
- On sync, a file whose hash still matches what was delivered updates
  silently — you never touched it, so there's nothing to protect.
- A file whose hash has **changed** — because you edited it — is treated as a
  conflict. You get a **keep / overwrite / diff** choice per file rather than
  either side winning by default.

This is what makes it safe to tune an agent's instructions, adjust a skill's
trigger phrasing, or fill in a steering file's project-specific sections, and
still take future registry updates without losing that work.

<Aside type="note">
There is no `link` command in this CLI. Getting the bundle into a project
happens at `kiroctl project new` / `kiroctl open` time, and staying current
after that is `kiroctl sync`.
</Aside>

## What's safe to customize

- **Steering** — durable, project-specific facts and standards.
- **Skills** — the trigger phrasing and steps of any `SKILL.md`.
- **Agents** — an agent's instructions, model pin, or skill list.

## Recommended workflow

1. Edit the file directly — no special mode needed.
2. Keep changes scoped and purposeful; you'll be reviewing them again at the
   next `sync` diff.
3. Next time you run `kiroctl sync`, choose **diff** on anything flagged as
   changed, and decide **keep** or take the upstream version deliberately.

<Aside type="tip">
If you find yourself making the same customization on every project, that's a
sign it belongs in the registry itself rather than as a per-project edit. Raise
it so everyone gets it by default.
</Aside>
