---
title: Steering
description: The five always-on rule files every agent loads on every turn.
---

Steering files are loaded into context on **every turn**, not on demand — a
standing token cost. That's why there are only five, each short and durable.
Anything situational belongs in a skill instead, loaded only when triggered.

## `00-conduct`

Be critical by default: challenge assumptions and name risks before offering
improvements. Evidence before "done" — root-cause first, one hypothesis at a
time, red-green verification, both directions checked, siblings swept. Report
outcomes faithfully, including partial or skipped work, without hedging.

## `10-token-efficiency`

Delegate gathering to sub-agents and keep judgement — synthesis and validation
stay in the main session, never the gathering itself. Model routing: Opus
orchestrates, Sonnet builds, never Haiku, never `auto`. Defines the
inline-only carve-out — paid-API bulk loops, bulk production writes, and
irreversible migrations run inline from the main session, never delegated.

## `20-engineering`

Reuse before you create — search by behavior, not filename, and extend the
existing owner of a concern. Fix at the owning layer, then sweep for sibling
implementations. Branch and PR discipline: never commit directly to a
protected branch, verify the build before pushing. ADO work reporting is
standard practice, not something to ask permission for.

## `30-qa-and-mission`

When to invoke `design`, `qa`, and `mission` — automatically after front-end
or functionality changes, and at the end of any mission phase that changed
product surface. The three QA non-negotiables: staging never production,
every page rendered in a real browser, and two-gate verdicts (`WORKS` +
`MATCHES INTENT`). The reversibility rule for mid-mission forks: two-way doors
get decided and logged, only genuine one-way doors — money, auth, destructive
production operations, external sends, schema migrations — stop the run.

## `40-secrets`

Never read, display, or expose secrets or credentials — `.env` files, key
files, credential stores, tokens. Redact secret values from any command output
or file content before showing it. Reference a secret by its key name, never
its value.
